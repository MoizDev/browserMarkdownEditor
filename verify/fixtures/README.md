# Reproducible browser inputs

**Implementation-phase bar:** charter §0 supersedes review/proof requirements below: clean static
checks and one real-app sanity run (light/dark screenshots looked at). Existing mutant controls
are kept for the post-K7 review phase; do not run new reviewer proofs now.

These are data generators, not tests. They never import `src/` or call app code. Behaviour is checked
only by opening the generated files in the real app through a headless-browser run. Do not add a
unit-test runner, `.test`/`.spec` files, or in-source assertions.

## Layout and ownership

- `<stream>/generators/*.mjs`: plain Node ESM (`core`, `pdf`, `platform`, `whiteboard`).
- `<stream>/manifest.json`: one entry per fixture, including sidecar oracles and assets.
- `lib/`: shared seeded randomness, output/hash protocol and deterministic PDF helpers.
- `external.manifest.json`: public download identities and per-file rights/admission status.
- Generated bytes, downloads and browser captures live outside the repository in the caller's
  scratch directory. Never commit a generated vault or PDF. Small historical samples require a
  separate per-file source/licence record before admission.

The PDF lanes own `pdf/generators/`; the fixture lane reviews and adopts their work. Geometry is
GEN-01 under `platform/generators/` (shared by PDF and X-REGISTER), not a second independent PDF
geometry corpus. Other PDF GEN IDs retain the names in the PDF fixture plan.

## Generator CLI and output

Every generator accepts `--out <directory> --seed <uint32>`; optional size switches are explicit
(e.g. `--notes 1000` or `--pages 876`). No positional defaults based on cwd, environment, machine or
clock. Write only below `--out`; use portable `/`-separated relative output names, reject traversal,
and refuse an existing output file. Caller chooses a fresh empty output directory for each run.

Print exactly one JSON line per emitted file to stdout:

```json
{"file":"geometry.pdf","sha256":"<64 lowercase hex characters>","bytes":1234}
```

`file` is relative to `--out`. Send diagnostics to stderr. Nonzero exit is failure; partial output is
not an accepted fixture. Include oracle JSON files in the same output protocol and in the manifest.
Write files in a stable declared order, encode authored text as UTF-8 with LF newlines, and end JSON
and Markdown with one LF. Use binary buffers for PDF/image output. Do not embed absolute paths.

## Determinism and PDF metadata

Use an explicit seeded PRNG only. No `Math.random`, current date/time, performance clock, locale,
environment or filesystem enumeration order may affect bytes. Sort portable names by code point,
not `localeCompare`. Same seed, arguments and dependency lock must produce byte-identical output
on independent invocations. A seed is an unsigned 32-bit integer, including zero.

Repository libraries such as `pdf-lib` are allowed; app imports are not. Pin every PDF creation and
modification date to `2000-01-01T00:00:00.000Z`, every document ID to a deterministic digest of the
fixture ID, generator version and seed, and producer/creator strings to fixed values. Disable
implicit metadata updates when loading PDFs. Set any library-internal random suffix seed if the
writer uses one. No system fonts, external artwork or copied article text. The shared PDF helper
will enforce these defaults; raw PDF writers must do the equivalent and record the writer version.
Font/codec assets need their own pinned hashes and redistribution notices, not a blanket generator
licence. A generated malformed PDF must be labelled negative/repairable, never a valid golden.

## Stream manifest (schema 1)

Top level: `{ "schema": 1, "stream": "pdf", "fixtures": [...] }`. Each record contains:

- `id`: stable role (PDF names use `GEN-xx` plus an explicit variant suffix).
- `file`: portable path relative to that generator invocation's `--out`.
- `tier`: `1` for generated; `licence` and `sourceNotice` for this file's actual rights.
- `purpose` and `gates`: what it exercises and the consuming gate IDs.
- `sha256`, `bytes`: exact committed identity, regenerated only by a reviewed corpus change.
- `generator`: repository-relative `.mjs` path; `version`: integer; `seed`: uint32;
  `args`: extra CLI switches as an array (do not repeat `--out`/`--seed`).
- Our newly authored outputs use `licence: "NOASSERTION"`, `proposedLicence: "CC0-1.0"` until the
  owner approves a licence; no repository licence or plan proposal grants redistribution rights.
- Optional `pages`, `features`, `expected`, `knownFailures`, `validity` (valid/repairable/invalid).
  `expected` names independent landmark/string/attachment oracles; old broken output is not truth.

Every emitted file has its own record; one generator invocation may produce many records. A run
records actual fixture IDs and hashes, not anonymous renamed samples. Never edit a fixture or its
hash merely to turn a gate green. New rights-clean authored text/geometry needs an explicit approved
licence before redistribution; third-party rights remain separate. Rights-unverified old evidence
is not admitted, even when the bytes are locally available.

## External inputs

Each external record has `id`, `url`, `sha256`, `bytes`, `licence`, `sourceNotice`, `gates` and
`admission` (`approved` or `hold`). Only public HTTPS URLs without credentials are eligible.
Fetch is explicit opt-in and verifies size and SHA-256 before atomically admitting bytes into an
external hash-addressed cache. Missing, changed or rights-blocked required input means **not run**,
never pass. No private vault content, names or paths enter this manifest or a network request.

## Acceptance and losses

V-05's browser run generates each registered invocation twice in fresh scratch directories,
compares the file bytes and committed manifest identities, then opens the generated all-constructs
note through the real file tree in Reading mode, saves screenshots, and opens GEN-01 through the
app's PDF pane, asserting its page id and colored fiducial pixels from a screenshot (never acquiring
the app's canvas context). The primary mutant changes the checker embed in the generated vault's
actual seeded note and must fail a **browser** image witness. A clock-reading generator is only a
second, preparation-level control. Determinism on this one machine does not cover the required second
machine. Browser identity, visible note content and image load are witnesses; merely creating files
or seeing a tree is not a passing run.

Gate contract: **witness** = authored note screenshots, decoded checker images and colored PDF
fiducials; **identity** = named OPFS vault, Reading-only editor, exact PDF page marker and pinned
browser and installed driver on a production preview; **mutant** = scratch-only vault generator
that inserts a missing image in the exact note the browser opens;
**false pass excluded** = creating files or mounting an empty pane without consuming the fixture;
**loss** = one machine, one positive vault/PDF observation, not all generated stress/adversarial
inputs exercised. Identically wrong generated bytes can still be deterministic: independent
oracles, review and each consuming stream's browser gates remain necessary.

## Shared APIs and registered corpus

`lib/cli.mjs`: `parseArgs(argv, extraSwitches)` requires `--out` and `--seed`; `uint32(value, name)`
validates unsigned integers. `lib/random.mjs`: `seededRandom(seed)` returns a `[0,1)` draw function.
`lib/output.mjs`: `fixtureWriter(out)` returns async `(file, content) => {file, sha256, bytes}` and
prints that record; `jsonBytes(value)` writes stable readable JSON plus LF; `sha256(bytes)` and
`writeManifest(path, stream, fixtures)` share the protocol. Output dirs must be caller-controlled,
not contain attacker-controlled symlinks, and are never the user's vault.

`lib/pdf.mjs`: `createDeterministicPdf(identity)`, `loadDeterministicPdf(bytes, identity)` and
`saveDeterministicPdf(document, identity)` use `{id, version, seed}`. They pin dates, IDs, metadata
and the pdf-lib resource-name RNG. They are Node-only tools, never imported into app code.

`catalog.mjs` explicitly registers the V-05 invocations (seed 123456789). Vault fixtures are JSON
containers of `{path, encoding, content}` files, not physical copies committed to the repository;
`noteCount` counts exactly N Markdown notes including the two named witnesses, plus image assets.
The bundle hash covers all contained paths and bytes. Browser runs materialize those entries in a
named OPFS folder through `createWritable`, then use **Open Vault** and the actual file tree.

V-08's separately registered save-path variant replaces line 4 of the mixed note with the sole
`![[save-only.png]]` reference, staying at exactly 10,000 lines; `.Assets/save-only.png` has a
unique name and the sidecar gives the exact before/after hashes. Deleting that one line leaves
9,999 lines and no reference to that asset. Existing mixed-note bytes/hashes are untouched.
V-08's mixed start-up composition is explicit: vault-1000 + GEN-01 + the original 10k mixed note,
restoring `Welcome.md` or `geometry.pdf`. Its bundle records each source hash and the cold/warm,
first-pixels/readable, bytes/requests, long-task and worker-start metrics it serves.

GEN-01's oracle names PDF-default-space points and page-local top-left coordinates, including
UserUnit, crop origin and clockwise page rotation. Matrices use `[a,b,c,d,e,f]` with
`x' = a*x + c*y + e`, `y' = b*x + d*y + f`. It is the canonical platform corpus; the PDF manifest
references the same generator/hash. The manifest's `$ROOT` placeholder is the corpus scratch root
when resolving the damaged-file generator's `--input` argument. Negative boxes and damaged files
are not renderability goldens.
Never open hostile inputs in a native viewer; use only isolated browser/worker runs with limits.

## Running V-05

Use the run's `bme-lock` and scratch Vite recipe; the server must already serve the production app
on a seat-owned port. Chrome for Testing is pinned by `verify/browser-pin.json`; no npx-cache driver.
Artifacts go into a fresh directory outside the repo. The ordinary gate is:

```sh
bme-lock run -w 2 -- node verify/fixtures/run-v05.mjs \
  --out /absolute/scratch/v05-run --url http://localhost:6180 \
  --dist /absolute/scratch/dist --block-external
```

`--browser-mutant` must reach Reading mode in the real app and exit 1 with **BROWSER witness**
for its missing checker image. It patches the vault generator's `Every construct.md` entry, not the
standalone notes module that the vault imports. Both a/b generations stay deterministic; only the
declared mutated bundle's hash/size is exempted from the frozen manifest (original and actual hashes
are reported), and every other record still must match. It never rewrites a manifest.

`--clock-mutant` is a separate preparation control: it exits 1 with **V-05 determinism** before
browser launch, and is **not** the gate's behavioural mutant. Both mutations require one exact
scratch-generator anchor; stale anchors fail loudly. Mutants cannot be combined or write manifests.

Off-origin blocking is **opt-in** (`--block-external`), with the mode and every blocked URL recorded;
without that flag the run does not install a network blocker. The driver version is read from the
installed Playwright package and checked against the pin, not merely copied from it. The common
picker/seeder and buildIdentity/bindServedBodies replace the old skill sketch. Functional binding
records its uncached raw-route mode and actual served code hashes; this is not a timing run.

`--record-manifests` is the explicit corpus-extension arm: it adds identities only after the
same real-app witnesses pass and refuses to replace or remove an existing file's hash/size.
A reviewed corpus change needs a new fixture identity, not a rewritten old hash. The normal run
refuses any changed committed identity (VER-06). Never use this as an automatic rebaseline. `report.json` and PNG captures
stay in the run directory; `losses` states the unexercised second machine and real-disk path.

For externals, `node verify/fixtures/fetch-external.mjs --cache /absolute/scratch/fixtures-cache OLD-R4`
never fetches implicitly; add `--fetch` only for an approved public input. It emits `available` or
`not run` JSON, and exits 2 for any unavailable required ID. Every current historical record is on
rights hold, even if its old bytes are cached. No external download was performed to author V-05.
