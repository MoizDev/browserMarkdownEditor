# Reproducible browser inputs

These are data generators, not tests. They never import `src/` or call app code. Behaviour is checked
only by opening the generated files in the real app through a headless-browser run. Do not add a
unit-test runner, `.test`/`.spec` files, or in-source assertions.

## Layout and ownership

- `<stream>/generators/*.mjs`: plain Node ESM (`core`, `pdf`, `platform`, `whiteboard`).
- `<stream>/manifest.json`: one entry per fixture, including sidecar oracles and assets.
- `lib/`: shared seeded randomness, output/hash protocol and deterministic PDF helpers.
- `external.manifest.json`: public download identities and per-file rights/admission status.
- Generated bytes, downloads and browser captures live outside the repository in the caller's
  scratch directory. Never commit a generated vault or PDF. Small historical samples require a
  separate per-file source/licence record before admission.

The PDF lanes own `pdf/generators/`; the fixture lane reviews and adopts their work. Geometry is
GEN-01 under `platform/generators/` (shared by PDF and X-REGISTER), not a second independent PDF
geometry corpus. Other PDF GEN IDs retain the names in the PDF fixture plan.

## Generator CLI and output

Every generator accepts `--out <directory> --seed <uint32>`; optional size switches are explicit
(e.g. `--notes 1000` or `--pages 876`). No positional defaults based on cwd, environment, machine or
clock. Write only below `--out`; use portable `/`-separated relative output names, reject traversal,
and refuse an existing output file. Caller chooses a fresh empty output directory for each run.

Print exactly one JSON line per emitted file to stdout:

```json
{"file":"geometry.pdf","sha256":"<64 lowercase hex characters>","bytes":1234}
```

`file` is relative to `--out`. Send diagnostics to stderr. Nonzero exit is failure; partial output is
not an accepted fixture. Include oracle JSON files in the same output protocol and in the manifest.
Write files in a stable declared order, encode authored text as UTF-8 with LF newlines, and end JSON
and Markdown with one LF. Use binary buffers for PDF/image output. Do not embed absolute paths.

## Determinism and PDF metadata

Use an explicit seeded PRNG only. No `Math.random`, current date/time, performance clock, locale,
environment or filesystem enumeration order may affect bytes. Sort portable names by code point,
not `localeCompare`. Same seed, arguments and dependency lock must produce byte-identical output
on independent invocations. A seed is an unsigned 32-bit integer, including zero.

Repository libraries such as `pdf-lib` are allowed; app imports are not. Pin every PDF creation and
modification date to `2000-01-01T00:00:00.000Z`, every document ID to a deterministic digest of the
fixture ID, generator version and seed, and producer/creator strings to fixed values. Disable
implicit metadata updates when loading PDFs. Set any library-internal random suffix seed if the
writer uses one. No system fonts, external artwork or copied article text. The shared PDF helper
will enforce these defaults; raw PDF writers must do the equivalent and record the writer version.
Font/codec assets need their own pinned hashes and redistribution notices, not a blanket generator
licence. A generated malformed PDF must be labelled negative/repairable, never a valid golden.

## Stream manifest (schema 1)

Top level: `{ "schema": 1, "stream": "pdf", "fixtures": [...] }`. Each record contains:

- `id`: stable role (PDF names use `GEN-xx` plus an explicit variant suffix).
- `file`: portable path relative to that generator invocation's `--out`.
- `tier`: `1` for generated; `licence` and `sourceNotice` for this file's actual rights.
- `purpose` and `gates`: what it exercises and the consuming gate IDs.
- `sha256`, `bytes`: exact committed identity, regenerated only by a reviewed corpus change.
- `generator`: repository-relative `.mjs` path; `version`: integer; `seed`: uint32;
  `args`: extra CLI switches as an array (do not repeat `--out`/`--seed`).
- Optional `pages`, `features`, `expected`, `knownFailures`, `validity` (valid/repairable/invalid).
  `expected` names independent landmark/string/attachment oracles; old broken output is not truth.

Every emitted file has its own record; one generator invocation may produce many records. A run
records actual fixture IDs and hashes, not anonymous renamed samples. Never edit a fixture or its
hash merely to turn a gate green. New rights-clean authored text/geometry needs an explicit approved
licence before redistribution; third-party rights remain separate. Rights-unverified old evidence
is not admitted, even when the bytes are locally available.

## External inputs

Each external record has `id`, `url`, `sha256`, `bytes`, `licence`, `sourceNotice`, `gates` and
`admission` (`approved` or `hold`). Only public HTTPS URLs without credentials are eligible.
Fetch is explicit opt-in and verifies size and SHA-256 before atomically admitting bytes into an
external hash-addressed cache. Missing, changed or rights-blocked required input means **not run**,
never pass. No private vault content, names or paths enter this manifest or a network request.

## Acceptance and losses

V-05's browser run generates each registered invocation twice in fresh scratch directories,
compares the file bytes and committed manifest identities, then opens the generated all-constructs
note through the real file tree in Reading mode and saves a screenshot. A clock-reading generator
mutant must fail this same run. Determinism on this one machine does not cover the required second
machine. Browser identity, visible note content and image load are witnesses; merely creating files
or seeing a tree is not a passing run.
